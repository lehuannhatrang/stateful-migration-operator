# 2026-07-07

## Single-cluster CheckpointBackup install and deploy/ restructure

### Added
- `config/checkpoint-backup-single-cluster/` kustomize overlay: bundles the
  CheckpointBackup CRD, namespace, RBAC, PVC, and DaemonSet with no Karmada or
  management-cluster dependency. Image is resolved via a single `images`
  transformer. Render with
  `kubectl kustomize --load-restrictor LoadRestrictionsNone config/checkpoint-backup-single-cluster`.
- `deploy/single-cluster/install.sh`: thin installer wrapping the overlay.
  Options for image override, registry credentials (creates the
  `registry-credentials` secret), PVC storage class/size overrides, kube
  context/kubeconfig targeting, and `--dry-run` (renders locally, no cluster
  access required).
- `deploy/single-cluster/uninstall.sh`: removes controller resources; `--purge`
  also removes the CRD and namespace.
- `deploy/single-cluster/README.md` and `deploy/README.md` (scenario chooser).

### Changed (restructure)
- Reorganized `deploy/` by scenario. Existing management-cluster / Karmada
  assets moved to `deploy/multi-cluster-karmada/` (all-in-one.yaml,
  deployment.yaml, rbac.yaml, service.yaml, namespace.yaml, karmada-secret.yaml,
  setup-karmada.sh, deploy.sh, README.md).
- Updated references broken by the move:
  - root `deploy.sh`: `deploy/all-in-one.yaml` -> `deploy/multi-cluster-karmada/all-in-one.yaml`.
  - `deploy/multi-cluster-karmada/deploy.sh`: `../config` -> `../../config`.
  - `deploy/multi-cluster-karmada/setup-karmada.sh`: deploy hint path.
  - `examples/workload-example/deploy-complete.sh`: deploy hint path.
  - `README.md`, `DEPLOYMENT_GUIDE.md`, `deploy/multi-cluster-karmada/README.md`:
    stale `deploy/*.yaml` and relative example paths.

### Removed
- `deploy/checkpoint-backup-daemonset.yaml` (duplicate of
  `config/checkpoint-backup/daemonset.yaml`).

### Validation
- Overlay renders successfully (7 resources, no Karmada objects).
- `bash -n` passes for all touched scripts; installer dry-run exits 0 for
  default and full-override invocations, and fails as expected when
  `--registry-user` is set without `--registry-pass`.
